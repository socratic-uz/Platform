# High-Performance & Low-Latency Engineering Standards

## 1. Главные метрики качества кода
При каждом архитектурном и техническом решении код оценивается по критериям:
1. **CPU & Throughput**: Минимизация тактов процессора, избегание блокировок потоков (async-first, lock-free, `Channel<T>`).
2. **RAM & GC Pressure**: Минимизация аллокаций в Gen0/Gen1, полное устранение аллокаций в LOH (Large Object Heap).
3. **Latency**: Предсказуемое время отклика на 99.9-м процентиле (p99/p99.9).
4. **Startup Time**: Мгновенный запуск микросервисов и терминалов благодаря Native AOT и отсутствию runtime reflection/JIT.

## 2. Zero-Allocation & Zero-Copy Patterns

### Предпочитать:
- **`Span<T>` и `ReadOnlySpan<T>`**: Для парсинга строк, протоколов, сетевых буферов и IKPU кодов без создания промежуточных `string` объектов.
- **`Memory<T>` / `ReadOnlyMemory<T>`**: Для асинхронных операций с буферами.
- **`ArrayPool<T>.Shared`**: Для временных буферов сериализации, ESC/POS команд и сжатия. Обязательный возврат в `finally`:
  ```csharp
  var buffer = ArrayPool<byte>.Shared.Rent(bufferSize);
  try
  {
      // Выполнение операции
  }
  finally
  {
      ArrayPool<byte>.Shared.Return(buffer);
  }
  ```
- **`ValueTask` и `ValueTask<T>`**: Для асинхронных методов в горячих путях, которые часто завершаются синхронно (например, возврат значения из локального кеша).
- **`IAsyncEnumerable<T>`**: Для потоковой передачи больших коллекций данных (каталог, заказы) без предварительной аллокации `List<T>`.
- **`System.IO.Pipelines`**: Для высокоскоростной потоковой обработки байтов с сетевых сокетов, термопринтеров и камер.
- **`readonly struct`**: Использование структур вместо классов для DTO и Value Objects там, где жизненный цикл локален и не вызывает boxing.

### Избегать:
- Вызовов тяжелых цепочек LINQ (`.Where().Select().OrderBy().ToList()`) в горячем коде (tight loops, обработка кадров, транзакционный путь). Заменять на `for`/`foreach` или `Span`-итераторы.
- Боксинга значимых типов (`object o = myInt`).
- Замыканий (`closures`) в лямбда-выражениях, приводящих к скрытым аллокациям экземпляров классов компилятора.
- Конкатенации строк (`+`) в циклах — использовать `StringBuilder` с предварительно заданной емкостью или `DefaultInterpolatedStringHandler`.

## 3. Чеклист архитектурного Review перед каждым ответом (Principal Mindset)
Перед выдачей любого решения или написанием кода мысленно проведи аудит:
1. **Где будут аллокации?** Можно ли сократить создание объектов в куче?
2. **Где используется reflection?** Исключен ли reflection в пользу compile-time генерации?
3. **Совместимо ли решение с Native AOT?** Нет ли тримминг-предупреждений?
4. **Какая будет latency?** Нет ли блокирующих синхронных вызовов (`.Result`, `.Wait()`)?
5. **Что произойдет при 1 миллионе пользователей / заказов?** Как поведет себя партиционирование ScyllaDB, Kafka и память Redis?
6. **Где появится потенциальный bottleneck?** (Сетевой сокет, serialization, GC freeze, thread pool starvation).
